# ⚡ Sprint 5: Caching & Performance Layer

> **الحالة:** مكتمل بنجاح ✅  
> **الهدف:** بناء طبقة تخزين مؤقت متقدمة وخفيفة لحماية حصة الـ API وتجنب حظر الطلبات (Rate Limiting 429)، مع دعم هجين للذاكرة المحلية وخادم Redis بنمط Fallback التلقائي.

---

## 🏗️ القرارات الهندسية والمعمارية (Architecture Decisions)

1. **نمط الاستراتيجية والمحول (Strategy & Adapter Pattern):**
   * واجهة موحدة `BaseCache` تضمن قابلية تبديل محرك التخزين دون تعديل كود `ForexService`.
   * دعم التبديل التلقائي لـ `MemoryCache` إذا تعذر الاتصال بخادم Redis.

2. **نمط التخزين عند الطلب (Cache-Aside Pattern):**
   * فحص الكاش أولاً عند طلب السعر؛ وفي حالة وجوده (`Hit`) يُعاد السعر فوراً دون استهلاك استدعاءات الشبكة.
   * في حالة غيابه (`Miss`)، يُجلب من المزود الخارجي ويُخزّن في الكاش مع مدة صلاحية (TTL) محددة.

3. **حساب الإحصائيات واستمراريتها:**
   * استخدام `INCR` في Redis لحفظ إجمالي الـ Hits والـ Misses واستعراضها عبر أمر `forex status`.
